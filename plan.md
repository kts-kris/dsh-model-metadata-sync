# Implementation plan: safe model metadata synchronization

Status: Approved
Baseline: spec.md v1.0.0; research.md; upstream 342d111b1ca41db05162bf50d70eba9cb19e6f19

## Strategy

Keep the upstream bundle and its display capabilities, but replace its unsafe model-write path with a fail-closed preview-and-confirm transaction. Preserve the complete existing DSH model objects; keep plugin-only metadata and provenance separate from the DSH schema. Default scheduling can discover but must never apply. Disable inherited rollback and updater behaviors until they can operate on fork-owned, complete, revision-checked state.

## Components and responsibilities

1. **Identity and packaging** (`package.json`, `cordis.patch.yml`, client/host entry files): rename package, client ID, slots, namespace, private state path, routes, updater and project documentation to `dsh-model-metadata-sync`; preserve upstream license. Isolate the `modelSync`/`modelSyncRunner` service registrations, environment variables, pricing/probe caches, old-state migration paths and DOM style fallbacks; never reuse or remove an original plugin style tag. Declare DSH compatibility for the actual target runtime and independently test npm peer resolution. Provide valid localized metadata and an original redistributable icon. Disable upstream updater until independently safe. Covers AC-9, AC-11, AC-13.
2. **Authenticated upstream discovery** (`lib/adapter-registry.js`, `lib/generic-adapter.js`, `lib/metadata-source.js`): preserve endpoint response data until validated; use only explicitly configured target origin and DSH credential service. Parse explicit OpenAI-compatible, documented fields (including complete exact `supported_reasoning_levels` array and explicit maps); preserve provenance separately. Do not equate input-only with combined context; reject unsupported, ambiguous, unbounded or incomplete result sets. Covers AC-1, AC-2, AC-6, AC-8, AC-15.
3. **Reference adapter** (`lib/reference-catalog.js`): retrieve one public models.dev snapshot without credentials, validate resource bounds and fetch time; require explicitly verifiable unique exact provider/model/protocol mapping. Return metadata and provenance without treating third-party entries as official or as evidence of actual downstream capability. Ambiguous IDs, absent mapping, stale cache and missing wire values stay unknown. Covers AC-3, AC-6, AC-8.
4. **Safe preview/reconciliation** (`lib/reconcile.js`, `lib/synchronizer.js`, `lib/history.js`): produce diff from original full current model objects and validated candidate values, preserve original nested fields/ordering and effective inherited values, append only selected unique IDs; unknown effective values block writes. Carry preview ID/digest over the user-approved diff. Disable deletion, hidden snapshot restore and unsafe ID rewrite paths. Covers AC-1, AC-4, AC-6, AC-7, AC-14, AC-15.
5. **Revisioned apply** (`lib/synchronizer-helpers.js`, `lib/synchronizer.js`): use one redacted settings descriptor snapshot/revision. When a provider has an explicit nonempty `models` list and no `modelOverrides`, use path-level `settings.mutate` on only its `models`, preserving every existing object. For an inherited built-in catalog, safely update only an existing model's exact `modelOverrides` entry if absence and inheritance are provable; if the route has no explicit list, never materialize a replacement list merely to add a model. Such new-model additions are previewed as unsupported until an order-preserving, inheritance-preserving and complete solution is proven. Handle provider scopes atomically with explicit per-provider outcomes. On conflict retry at most three times after reading and computing afresh; reject a changed approved diff and require another preview. Never reconstruct a whole settings section from redacted values. Covers AC-4, AC-5, AC-6, AC-8, AC-9.
6. **Presentation and consent** (`lib/client.js`, `lib/client/locales.js`, `lib/http.js`, `lib/routes/*`): show original vs candidate, provenance, freshness, unknowns, sanitized provider identity and protocol, explicit per-diff approval and maxTokens warning. Show nonofficial lookup disclosure and disable option. At the single Host commit authority, disable or replace every unapproved write/probe path: `/run`, `/selection`, scheduler, `/history/rollback`, `/import`, `/try`, `/batch-try`, `/probe/*`, updater and public runner; UI-only restrictions are insufficient. Bind server-side, single-use, expiring preview tokens to provider, endpoint identity, protocol, source, selection, exact diff and revision; never send or hash unredacted descriptor/headers. Price synchronization is independently opt-in. Use current DSH Host route authentication and origin checks. Covers AC-1, AC-3, AC-7, AC-8, AC-10, AC-12, AC-14, AC-15.
7. **Regression and integration** (`test/*.test.js`, package scripts): construct fake upstream responses and interleaved settings/credentials without real provider secrets; demonstrate red→green, source validation, inheritance, malformed/empty/paginated/redirect responses, conflicts, old state preservation, unique identities and user-visible warnings. Add a documented isolated current-DSH package install/load/unload smoke, without touching desktop profile. A separate reviewer checks test proof and adversarial cases. Covers AC-1 through AC-11, AC-14, AC-15.
8. **Publication**: after tests, security review, and proof of the package contents, publish the actual tested revision to public GitHub `kts-kris/dsh-model-metadata-sync` and npm `dsh-model-metadata-sync`; verify registry version and artifact hash/clean install. Submit only the catalog's one allowed YAML entry after the one-day age requirement, then report PR, CI, merge, npm publication, and Discover inclusion independently. Covers AC-13.

## Sources and data shape

See `contracts/metadata.md`. Do not make unattended inference calls, perform provider probes using real user credentials during development, or rewrite any live user profile. Use nonofficial references only by the approved exact-identity rule and expose uncertainty. A new upstream model may appear in preview even if all metadata is unknown; only user-selected IDs can be added.

## Dependencies, order and decisions

- Work begins with a new remote GitHub fork and a local feature branch, preserving original Git history and MIT license. No push before review.
- Offline tests and source contract precede changes to the UI and write routes. Identity renaming and metadata parsing can be developed in parallel on separate files.
- Disable unsafe inherited rollback and updater until a complete implementation is separately proven; document the changed behavior.
- CI/package check replaces upstream's missing scripts and must fail when zero tests run.
- Since user's npm account is logged in as `kts2kris`, package publication can be attempted only after all gates; browser or terminal challenges remain user-controlled.
- New fork age, catalog maintainers and index refresh are external constraints; keep the goal active and report concrete status rather than claiming acceptance.

## Risks and verification

- The published tree lacks its original scripts and tests; recreate only necessary build/check machinery and verify the shipped client corresponds to source.
- Upstream plugin can delete/alter existing models, read fixed endpoints, and use unsupported metadata fields; enumerate every mutating entry point, not just the normal discovery path.
- DSH default values and inherited model catalogs can look like explicit upstream metadata. If absent vs inherited cannot be established, do not materialize a replacement value.
- `contextWindow` is combined input+output while vendor `max_input_tokens` may mean input only. Reject semantic conversion without provider-specific evidence.
- Standard DSH discovery may return a local catalog rather than the configured gateway and does not retain effort wire mappings; upstream authority must come from a safely authenticated raw endpoint response and documented per-field semantics. A user-defined route name is not proof of upstream vendor identity.
- A redacted settings descriptor may still include secrets placed in ordinary `headers` or unknown fields. Client responses, diagnostics and hashes must use explicit safe projections, never entire descriptors or raw provider objects.
- The old plugin can recompute or retry a stale replacement even after a competing writer succeeds; refuse fork apply while an original writer is active for the same provider rather than claiming single-sided CAS makes both safe.
- Real installation proof must use a separately owned temporary profile/home and mock endpoints; do not use the active Desktop profile or interact with real upstream APIs.
