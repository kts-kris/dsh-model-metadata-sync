# Research: upstream model metadata synchronization

Status: Approved
Date: 2026-11-24

Evidence: the cited implementation statements are source observations; the reported baseline commands were run without executing the plugin. A separate reviewer checked the cited facts. Race outcomes and integration behavior remain unproven until exercised by tests.

## Existing system

- Upstream repository: `GooDAnDReaDY/dsh-model-sync`, cloned at commit `342d111b1ca41db05162bf50d70eba9cb19e6f19`; package version `0.5.33` (`package.json:1-4`). The bundled source is MIT licensed and retains the original copyright notice (`LICENSE:1-13`).
- Upstream package defines a DSH bundle and client entry (`package.json:21-34,43-54`) and uses `node --test` for tests (`package.json:66-72`). At checkout, `npm test` reported zero tests; `npm run check` failed because `scripts/build-client.mjs` is absent. The checked-out tree contains no test or scripts directories.
- Catalog discovery selects existing providers, sends discovery requests, normalizes records, calculates a reconciliation, and only proceeds with model-setting writes on successful changed results when not in dry-run mode (`lib/synchronizer.js:308-339,383-412,441-462`).
- `normalizeModel` builds a selected set of properties: IDs, context, output limits, input, compatibility, generic capabilities, `reasoningConfig`, and prices; its returned object does not include DSH's `reasoningEfforts` (`lib/models.js:45-92`). When explicit capacity values are absent, it consults the internal reference database (`lib/models.js:56-61`), whose lookup strips some ID suffixes and may search across providers (`lib/specs-database.js:1-10,121-154`). The normalizer infers some reasoning data from provider and model names (`lib/parsers/normalizers.js:350-389`).
- Reconciliation normalizes the existing and discovered lists before merging and spreads the discovered record after the existing record, so discovered capacities may replace configured capacities; nonempty discovered `input` also wins (`lib/reconcile.js:7-55`). When any other difference triggers application of the rebuilt list, existing `reasoningEfforts` and other non-normalized model fields may be lost; normalized diffing does not detect such loss in isolation (`lib/models.js:45-92,115-129`; `lib/reconcile.js:70-79`; `lib/synchronizer.js:441-453`).
- The apply path recomputes profile state through `replaceWithRetry` but inserts each `row.next` prepared before the write (`lib/synchronizer.js:441-453`); the retry helper reads a settings description and calls `settings.replace` with a revision (`lib/synchronizer-helpers.js:125-145`). A conflict can retry a previously computed models list; controlled interleaving is not yet tested. History snapshots normalize and selectively copy model fields, excluding `reasoningEfforts` and capping the list at 5,000 models (`lib/history.js:4-6,19-40`); rollback uses those snapshots to construct a replacement (`lib/synchronizer-helpers.js:171-191`).
- The package name and runtime identities occur across the bundle patch, module entry, client registration, HTTP routes, local state and updater (`cordis.patch.yml:2-4`; `lib/index.js:9-12,231-241`; `lib/client.js:1-2,850-854,2390-2400`; `lib/http.js:21`; `lib/state-store.js:34-50`; `lib/updater.js:321-325`).
- Existing lifecycle and selection logic can pass missing, deprecated, filtered or snapshot IDs as explicit removals even when `removeMissing` was not requested (`lib/synchronizer.js:388-412`). The built-in adapter registry includes fixed vendor endpoints (`lib/adapter-registry.js:25-51`) and the scheduler invokes price synchronization when enabled (`lib/scheduler.js:88-95`), so the exact destination for each credential and each additional background request is relevant to subsequent design.
- The current DSH installation is `0.2.3-alpha.2`. Its active `ctx.settings.mutate` contract accepts path operations with an optional expected revision; `ctx.llm.discoverModels` returns IDs, optional context/output limits and input modalities, but no per-level reasoning mapping (runtime `cordis_inspect`, Host `Service.listService` for `settings` and `llm`).
- DSH pi-ai model entries accept `contextWindow`, `maxTokens`, `input`, and `reasoningEfforts`; setting `maxTokens` explicitly also sets a request default (`/Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-llm-pi-ai/src/catalog.ts:603-639`).
- DSH treats missing `reasoningEfforts` as inheritance from an installed model; without one, reasoning is not declared (`/Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-llm-pi-ai/src/catalog.ts:720-737`). A boolean reasoning capability alone is not a level-to-wire mapping.
- The installed OpenAI SDK's Model shape declares an ID and basic identity but not capacity or effort levels (`/Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/openai/src/resources/models.ts:38-69`). The installed Anthropic SDK defines per-level support flags and nullable input/output capacities (`/Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@anthropic-ai/sdk/src/resources/models.ts:109-142,194-225`). These schemas do not prove what an arbitrary gateway returns. Upstream maps Anthropic's input-only `max_input_tokens` and Google's `inputTokenLimit` as `contextWindow` (`lib/parsers/normalizers.js:3-13`; `lib/adapter-registry.js:98-112`), whereas DSH describes `contextWindow` as a combined request/response context (`/Applications/DeepSeek Harness.app/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-llm-pi-ai/src/catalog.ts:609-617`).
- The user-selected community directory is generated from `awesome-dsh-plugin/awesome-dsh-plugin`; its contribution instructions request a single plugin YAML entry, a publicly accessible repository at least one day old, a `dsh-plugin` topic, and an installable bundle manifest (https://github.com/awesome-dsh-plugin/awesome-dsh-plugin/blob/main/contributing.md). The specific configured Discover index additionally depends on a published npm package associated with that repository; publication and later index inclusion require verification.
