# Amendment: bounded public reference snapshot

Date: 2026-11-25
Status: Accepted with conditional independent review; user authorized recommended choices by default
Authority: user approved models.dev-style nonofficial reference lookup, default enabled, and requested recommended choices by default; engineering must not claim unsupported source semantics.

## Verified external facts

- An unauthenticated identity-encoded GET of `https://models.dev/api.json` returned HTTP 200 and 6,918,790 bytes on 2026-11-25; the exact size and availability can change.
- The reference source's public worker documents full catalog endpoints and a type filter but no verified provider/model-specific JSON endpoint. Filtering to chat remained above the current 4 MiB limit in a separate read-only check.
- A locally replayed complete public catalog contained uniquely identified models with zero or internally inconsistent capacity values; rejecting the whole complete snapshot for any one unrelated model makes all valid reference records unavailable.

## Intended change

1. Keep the configured private upstream limit at 4 MiB per response. Permit a separately bounded **16 MiB** body based on actual bytes read only for the exact fixed unauthenticated `GET https://models.dev/api.json` reference snapshot (no query, fragment, userinfo, redirects, arbitrary headers, credentials or private address). Send the fixed `Accept-Encoding: identity` request header, require identity response encoding and reject any non-identity content encoding (including transparently decoded gzip/br), non-200 status, invalid/contradictory Content-Length, truncation or over-limit body. No caller can override either limit. Treat invalid UTF-8/JSON, duplicate or escaped-equivalent object keys, unbounded depth/chunks/keys/nodes, and incomplete transmission as whole-source failure.
2. Run reference download, strict parsing and structural projection in a single bounded, terminable worker; the parent enforces one 15-second absolute monotonic deadline from admission through worker startup, transport, parsing, projection and result delivery, and terminates the worker on timeout. Never publish late results; use a monotonic deadline and recheck it on every result. Permit one in-flight reference worker, refuse concurrent work rather than queue, and release its slot only after termination/exit is observed; allow retry after termination. Configure worker V8 resource limits to 128 MiB old generation, 16 MiB young generation and 4 MiB stack, independently of the body byte limit; no raw catalog is written to disk. Worker input cannot contain private endpoint URLs or credentials. Disable reference caching in this version (no HTTP cache, in-process snapshot reuse, or disk cache). The worker may deliver exactly one terminal result message containing at most 20,000 projected records and 8 MiB of UTF-8 encoded serialized JSON; exceeding either limit, message flooding, worker startup/delivery failure or abnormal exit returns unknown with no partial publication. No individual record may exceed 8 KiB encoded. The parent must bound message parsing and stage the first terminal result without publishing it. Any additional message is not parsed or accepted but marks a protocol violation; publish the staged result only after the worker exits normally within the same absolute deadline and no protocol violation occurred. Test large projected results, result-then-extra-message, result-then-abnormal-exit, worker crashes and exit failures. Before constructing the complete object graph, scan/count and bound JSON depth at 128 containers, body chunks at 65,536, total object-key occurrences at 1,000,000 and total JSON value occurrences at 2,000,000; exact boundary passes and exceeding one fails the complete snapshot. The 16 MiB byte cap and V8 worker heap limit are logical/heap bounds, not a hard process RSS or native-buffer limit. Existing private-upstream requests retain their 15-second per-request deadline, which is not a hard deadline for synchronous CPU parsing, and their 4 MiB cap. A stalled OS or parent event loop cannot be treated as a real-time guarantee.
3. After the entire document has passed transport, UTF-8, syntax and duplicate-key checks, validate its top-level/provider identity structure. An invalid root or root-level error marker makes the whole snapshot unavailable. A malformed provider, provider-level error marker, missing/wrong-type declared provider ID, or contradictory provider identity makes every affected provider unavailable; where a key and declared ID disagree, both identities are affected, and if that scope cannot be proved the entire snapshot fails. A malformed model, missing/wrong-type model ID, or malformed limit container must never be silently dropped; only if a single exact identity is independently provable may it remain an unknown tombstone. An object key alone does not prove identity unless the reviewed source schema explicitly makes it authoritative and no contradictory identity exists. Otherwise the affected provider or wider unknown scope fails. Never drop an identity-mismatched record and then claim another is uniquely matched. The same rule applies to model key/declared-model-ID mismatches within a provider: both identities are contaminated. Where aliases or conflicting records make the affected scope uncertain, reject the broader affected provider or the whole snapshot. An unassignable root ambiguity fails the whole snapshot. A missing individual limit is unknown only for that field; an absent entire limits object leaves all limits unknown. A uniquely identified model record with an invalid, nonpositive or contradictory *present* limit or an error marker remains represented as an explicit non-applicable `unknown` tombstone for that exact provider/model; it must not disappear and thereby fabricate a unique match. Aliases or identity conflicts that could affect uniqueness invalidate the affected identity scope rather than being filtered out. Valid unrelated models may be used only after exact identity and source proof.
4. Reference freshness, source labeling, user values, confirmation, credential separation and complete reasoning wire-evidence requirements are unchanged. A reference timestamp expresses local fetch age, not guaranteed source freshness. Unknown/zero remains unknown; never infer that zero means free or unsupported.

## Acceptance tests required

- Upstream 4 MiB and reference 16 MiB independently reject closed valid bodies of limit+1, with and without Content-Length, and accept exact-limit valid responses; bypassing either bound must fail tests.
- One-byte transport truncation, invalid UTF-8, duplicate JSON keys at root/nested/escaped levels and unknown target identity yield no applicable candidates. Tests use fake transport and no real credentials.
- A fully parsed snapshot containing both a valid exact model and an invalid unrelated model returns a known candidate for the valid identity, and an explicit unknown tombstone for the invalid identity; aliases, duplicate IDs and scope conflicts never produce false uniqueness. Before applying `limit.context` or `limit.output`, require independently reviewed source documentation for combined input/output context and output-token semantics, plus trusted Host exact endpoint/provider/model/protocol binding. An arbitrary URL string or a record's own claim is not independent proof; missing proof means unknown. Add negative fixtures for absent semantics proof, wrong protocol, identity without source proof and source proof without identity; synthetic bindings in tests must be labeled synthetic, not presented as proof of the user's actual endpoint.
- Keep no cross-origin credentials, no response/secret logging, no automatic application, and all existing model values protected. Explicitly test unrelated provider/model isolation and target contamination.
- With a fake clock and worker, verify 15 seconds bounds the complete reference fetch/parse, terminates network/worker, ignores late messages, limits concurrent work to one, and does not publish partial results. Separately exercise a real isolated worker with a deliberately blocked parser and short test deadline: assert actual worker exit, no late publish or cross-generation message acceptance, streaming cancellation, concurrent refusal through termination with no unbounded queue, and successful retry only after observed exit. At or after deadline, the parent must reject even when a result races the timer; termination/exit failure leaves the slot closed. Test exact depth, chunk, node/key count boundaries, decompression rejection and disabled caching; separately retain the private-upstream per-request deadline tests.
- A representative, redistributable minimal synthetic fixture shaped like the documented public schema is used in the suite. Live availability/size checks do not replace offline tests.

## Consequences

This is a targeted contract change, not proof that live reference data matches any user's private gateway. Correct endpoint/protocol binding and per-field source proof remain prerequisites, and effective settings/canonical IDs remain unknown when they cannot be proven. Neither npm publication nor catalog admission is authorized as complete by this amendment.
